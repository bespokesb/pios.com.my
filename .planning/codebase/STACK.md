# Technology Stack

**Analysis Date:** 2026-07-01

## Languages

**Primary:**
- PHP `^8.3` required (`composer.json`); local + production run PHP `8.4` (production is PHP 8.4-FPM). All application code under `app/`.

**Secondary:**
- Blade templates (`resources/views/`) for the few non-Filament pages; most UI is generated by Filament PHP classes, not hand-written Blade.
- CSS via Tailwind 4 (`resources/css/app.css`, plus `resources/css/filament/`). No hand-written JavaScript beyond the Vite entry — the app has **no** front-end JS framework.

## Runtime

**Environment:**
- PHP 8.4 (CLI reports `8.4.22`). Production: PHP 8.4-FPM behind nginx.
- Node.js used at build time only (Vite); **no Node runtime on the production server** — assets are built locally and rsynced up.

**Package Managers:**
- Composer for PHP. Lockfile present (`composer.lock`), locked versions cited below.
- npm for front-end. `package.json` present; `type: module`.

## Frameworks

**Core:**
- `laravel/framework` `v13.14.0` (`composer.json` `^13.8`) — application framework (routing, Eloquent ORM, queue, scheduler, mail, encryption).
- `filament/filament` `v5.6.6` (`composer.json` `^5.0`) — admin/panel UI layer. The entire back-office is built as Filament Resources, Pages, and Widgets. **Three panels** are registered (see below).
- `laravel/tinker` `v3.0.2` — REPL / artisan tinker (used heavily to verify deploys on the server).
- `stechstudio/filament-impersonate` `v5.5.0` — user impersonation from the admin panel. Wired into `app/Models/User.php`, `app/Filament/Resources/Users/Pages/EditUser.php`, and `app/Filament/Resources/Users/Tables/UsersTable.php`.

**Filament Panels** (`app/Providers/Filament/`):
| Panel | id | path | Notes |
|-------|-----|------|-------|
| Admin | `admin` | `/admin` | `->default()` panel; SysAdmin / PiosOwner (`AdminPanelProvider.php`) |
| Partner | `partner` | `/partner` | Partner role (`PartnerPanelProvider.php`) |
| Business | `business` | `/business` | Business Owner role; custom login `BusinessLogin` (`BusinessPanelProvider.php`) |

All three share the single `web` session; `canAccessPanel` is mutually exclusive per role (admins may enter all three).

**Testing:**
- `phpunit/phpunit` `12.5.29` (`composer.json` `^12.5.12`) — test runner. Config in `phpunit.xml`.
- `mockery/mockery` `^1.6` — mocking.
- `fakerphp/faker` `^1.23` — factory fake data (dev dependency; note factories/seeders require dev deps installed).
- `nunomaduro/collision` `^8.6` — CLI test/error output.
- Two suites in `phpunit.xml`: `Unit` (`tests/Unit`) and `Feature` (`tests/Feature`). Tests run against **SQLite in-memory** (`DB_CONNECTION=sqlite`, `DB_DATABASE=:memory:`), `MAIL_MAILER=array`, `QUEUE_CONNECTION=sync`, `CACHE_STORE=array`, `SESSION_DRIVER=array`. Pulse/Telescope/Nightwatch disabled in tests.
- Note: `composer.json` allows the `pestphp/pest-plugin`, but Pest is **not** installed — tests are plain PHPUnit.

**Build / Dev tooling:**
- `vite` `^8.0.0` with `laravel-vite-plugin` `^3.1` and `@tailwindcss/vite` `^4.0.0` (`package.json`, `vite.config.js`) — asset bundling.
- `tailwindcss` `^4.0.0` — utility CSS.
- `laravel/pint` `^1.27` (`v1.29.1`) — PHP code style / formatter (Laravel preset; no custom `pint.json`, so defaults apply).
- `laravel/pail` `^1.2.5` — live log tailing in dev (`php artisan pail`). **Dev-only** — a deploy pitfall exists where the cached package manifest references Pail's provider on prod; see INTEGRATIONS.md / deploy notes.
- `laravel/pao` `^1.0.6` — dev tooling.
- `concurrently` `^9.0.1` (npm) — runs the multi-process dev script.

## Database

- Application default connection: MySQL (`config/database.php` default is `sqlite` via env, but the app runs on MySQL database `pios_my` in dev and prod).
- Queue, cache, and session all default to the **database** driver (`config/queue.php`, `config/cache.php`, `config/session.php`) — no Redis. Filesystem default is `local` (`config/filesystems.php`).

## Configuration

**Environment:**
- Standard Laravel `.env` (present; never read for secrets). Custom config namespaces:
  - `config/pios.php` — `partner_monthly_customer_target` (advisory quota, default 100; env `PARTNER_MONTHLY_CUSTOMER_TARGET`).
  - `config/services.php` — third-party service creds incl. the `ustazai` WhatsApp blaster block (see INTEGRATIONS.md).
- Timezone `Asia/Kuala_Lumpur`; Malaysian phone normalization in `app/Support/Phone.php`.

**Build:**
- `vite.config.js` — Vite + Tailwind + Laravel plugin config.
- `phpunit.xml` — test env.

## Running the App

**All-in-one dev** (`composer run dev`, from `composer.json` scripts) runs four processes via `concurrently`:
```
php artisan serve                              # HTTP server (server)
php artisan queue:listen --tries=1 --timeout=0 # queue worker (queue)
php artisan pail --timeout=0                   # live logs (logs)
npm run dev                                    # Vite dev server (vite)
```

**Individual commands** (from `CLAUDE.md`):
```bash
php artisan serve      # Laravel HTTP server only
npm run dev            # Vite dev server only
npm run build          # build production assets (vite build)
php artisan test       # run the PHPUnit suite
php artisan migrate    # run migrations against MySQL
php artisan make:filament-user   # create a local Filament admin user
```

**Scheduled work** (`routes/console.php`):
- `GenerateMonthlyBusinessOwnerFees` runs `->monthlyOn(1, '00:30')` with `withoutOverlapping()->onOneServer()` (the `fees:generate-monthly` idempotent RM5 monthly fee).

## Platform Requirements

**Development:**
- PHP 8.4, Composer, Node/npm (for Vite), MySQL (`pios_my`).

**Production:**
- Ubuntu 24.04, nginx + PHP 8.4-FPM, MySQL, behind Cloudflare. systemd queue worker `pios-queue` + www-data crontab running `schedule:run`. No Node on the server. Full config/route/view/event caching (`php artisan optimize`). Details in INTEGRATIONS.md.
