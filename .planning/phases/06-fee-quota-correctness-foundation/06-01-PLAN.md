<objective>
Lay the correctness foundation that unblocks the Business Owner Fee Schedule (Phase 7) and Partner Monthly Customer Quota (Phase 8). This phase is small and mechanical: it adds the schema, enum, system audit user, and timezone scaffolding that make recurring fees impossible to double-bill and make month boundaries compute in Malaysia time.

Purpose: Pitfalls 1 (duplicate monthly fees), 2 (re-charged setup fee), 3 (UTC vs MYT month boundaries), and 6/12 (no audit actor for scheduled jobs) must be designed out BEFORE any fee-generation logic exists. This phase owns those prerequisites.

Output:
- `billing_period` column on `fees` + DB unique index `(business_owner_id, fee_type, billing_period)`
- Composite `(partner_id, created_at)` index on `customers` for partner-by-month quota counts
- `FeeType::BusinessOwnerSetup` enum case
- Idempotent `pios-system` user (seeder + `User::system()` resolver) — FND-06
- App timezone set to `Asia/Kuala_Lumpur` (env-driven, defaulting correctly)
- Automated tests proving the unique index blocks duplicates and the system user seeder is idempotent

Out of scope (Phases 7/8): the setup-fee generation hook, the monthly scheduled command, any quota counting, any UI.
</objective>
