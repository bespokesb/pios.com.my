<objective>
Turn the `/business` customer list (CustomerResource) into a segmented CRM list: per-stage tabs (All + Lead/Prospect/Customer/VIP) with scoped badge counts (CRM-04), name + phone search (CRM-04), and an inline, ownership-gated "Set stage" action that lets a Business Owner move their OWN customer between Lead/Prospect/Customer only (CRM-05) — VIP/Non-LOS stay out of scope because they require LOS/ABO fields this phase does not touch.

Purpose: Give a BO the core CRM verb ("how many prospects do I have? move this lead to a customer") without ever re-exposing the PII/LOS fields the form deliberately hides. Re-exposing `category` to the BO happens EXCLUSIVELY through this narrow inline action — never by un-guarding the form Section that hides IC/cost/PII (Pitfall 3).
Output: getTabs() on ListCustomers, a gated `setStage` Action on CustomersTable, bilingual labels in both lang files, and a Feature test proving scoped counts + search + own-customer stage change + VIP rejection + cross-BO refusal, with the full suite green.

Out of scope: ViewCustomer page (Phase 11), WhatsApp/Call actions (Phase 13), any change to CustomerForm sections, any new migration/model. ABSOLUTE INVARIANT: a BO only ever sees/manages their OWN customers — every count and action routes through the existing scoped query + CustomerPolicy.
</objective>

The list page resolves rows through the resource's scoped query — app/Filament/Resources/Customers/CustomerResource.php:
```php
public static function getEloquentQuery(): Builder
{
    $query = parent::getEloquentQuery();
    $user = auth()->user();
    return $user ? $query->visibleTo($user) : $query->whereRaw('1 = 0');
}
```
Use `CustomerResource::getEloquentQuery()` for the per-stage badge counts so counts inherit `visibleTo` (BO → own customers only). NEVER use a bare `Customer::query()` for the counts (that would leak cross-BO totals).

Filament v5.6 list tabs — getTabs(): array<string, Tab>, Tab from `Filament\Schemas\Components\Tabs\Tab` (verified in vendor). Tab supports `->badge(Closure|scalar)` (HasBadge) and `->modifyQueryUsing(Closure)` (filters the already-scoped table query). The active tab's modifier is applied on top of getEloquentQuery, so a tab modifier only needs `->where('category', ...)`.

Notification::make()->success()->title(...)->send(); })`. An Action collects input via `->schema([...])` (Filament v5.6 HasSchema; `Select` from `Filament\Forms\Components\Select`), and the typed `$data` array is passed to `->action(function (Customer $record, array $data) {...})`.

Ownership policy already enforces BO-owns-customer — app/Policies/CustomerPolicy.php:
```php
public function update(User $user, Customer $customer): bool
{ return $user->isAdmin() || ($user->isBusinessOwner() && $user->businessOwner?->id === $customer->business_owner_id); }
```
Gate the action with `auth()->user()?->can('update', $record)` (visible) AND re-check inside `->action()` via `abort_unless(... can('update', $record), 403)` (defense-in-depth against a crafted Livewire call).

    ```php
    Action::make('setStage')
        ->label(__('pios.customer.stage.action'))
        ->icon('heroicon-o-arrows-right-left')
        ->modalHeading(__('pios.customer.stage.action'))
        ->modalSubmitActionLabel(__('pios.customer.stage.action'))
        ->visible(fn (Customer $record): bool => (auth()->user()?->can('update', $record) ?? false)
            && in_array($record->category, self::settableStages(), true))
        ->schema([
            Select::make('category')
                ->label(__('pios.customer.stage.label'))
                ->options(self::settableStageOptions())
                ->default(fn (Customer $record): ?string => $record->category?->value)
                ->required(),
        ])
        ->action(function (Customer $record, array $data): void {
            abort_unless(auth()->user()?->can('update', $record) ?? false, 403);

            $target = CustomerCategory::tryFrom($data['category'] ?? '');
            if ($target === null || ! in_array($target, self::settableStages(), true)) {
                throw ValidationException::withMessages([
                    'category' => __('pios.customer.stage.invalid'),
                ]);
            }

            $old = $record->getOriginal();
            $record->update(['category' => $target]);

            app(AuditLogger::class)->log(
                actor: auth()->user(),
                event: 'updated',
                auditable: $record,
                oldValues: $old,
                newValues: $record->fresh()->getAttributes(),
            );

            Notification::make()->success()->title(__('pios.customer.stage.updated'))->send();
        }),
    ```
