<objective>
CRM-06 — one-tap WhatsApp + Call. Add two Filament record Actions ("WhatsApp", "Call") to the customers table rows AND the ViewCustomer detail-page header. The WhatsApp action opens `https://wa.me/60…` in a new tab; the Call action opens `tel:+60…`. Both links are built through the already-unit-tested `App\Support\Phone` helper (Phase 10) and both actions are hidden when the phone normalizes to null. No schema changes.

Purpose: Give a Business Owner a friction-free way to contact their own customers without re-typing numbers, while reusing the existing `getEloquentQuery()->visibleTo()` ownership gate so a BO can never act on another BO's customer.
Output: One reusable `CustomerContactActions` factory (single source of truth for both surfaces), wired into `CustomersTable` recordActions and `ViewCustomer` header actions, bilingual labels, and a feature test proving url-building + hidden-when-blank + ownership isolation, with the full suite green.

Cross-phase ordering (read carefully): this phase consumes two artifacts built earlier in the same milestone — `App\Support\Phone` from Phase 10 (`toWhatsApp` returns bare digits like `60123456789`; `toTel` returns `+60123456789`; blank → null) and `app/Filament/Resources/Customers/Pages/ViewCustomer.php` from Phase 11 (CRM-03 ViewRecord). Phases run in roadmap order (10 → 11 → 12 → 13), so both files exist when this plan executes. Do NOT recreate them.

Out of scope: product share/promote (PLST-04, Phase 15), notes/follow-ups UI, any schema change, any pre-filled message text (Call/WhatsApp here are contact links only, no `?text=`).

App\Support\Phone (Phase 10 — ALREADY BUILT, returns digits/E.164, NOT a full URL):
```php
Phone::toWhatsApp('0123456789')   === '60123456789'   // bare digits, no scheme
Phone::toWhatsApp('012-345 6789') === '60123456789'
Phone::toWhatsApp('+60123456789') === '60123456789'
Phone::toWhatsApp('') /* or null */ === null
Phone::toTel('0123456789')        === '+60123456789'  // tel uses the + form
Phone::toTel('')                  === null
```
So the link is built by PREPENDING the scheme: `'https://wa.me/'.Phone::toWhatsApp($hp)` and `'tel:'.Phone::toTel($hp)`.

    Create `app/Filament/Resources/Customers/Actions/CustomerContactActions.php` — a stateless factory so the SAME action definitions feed both the table rows and the ViewCustomer header (one source of truth → one thing to test):
    ```php
    <?php

    namespace App\Filament\Resources\Customers\Actions;

    use App\Models\Customer;
    use App\Support\Phone;
    use Filament\Actions\Action;

    class CustomerContactActions
    {
        public static function whatsApp(): Action
        {
            return Action::make('whatsapp')
                ->label(__('pios.customer.contact.whatsapp'))
                ->icon('heroicon-o-chat-bubble-left-right')
                ->color('success')
                ->url(fn (Customer $record): string => 'https://wa.me/'.Phone::toWhatsApp($record->hp_no))
                ->openUrlInNewTab()
                ->visible(fn (Customer $record): bool => Phone::toWhatsApp($record->hp_no) !== null);
        }

        public static function call(): Action
        {
            return Action::make('call')
                ->label(__('pios.customer.contact.call'))
                ->icon('heroicon-o-phone')
                ->url(fn (Customer $record): string => 'tel:'.Phone::toTel($record->hp_no))
                ->visible(fn (Customer $record): bool => Phone::toTel($record->hp_no) !== null);
        }
    }
    ```
